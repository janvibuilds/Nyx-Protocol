================================================================================
                              DATA FLOW SUMMARY
================================================================================

  1. Client Frontend ──(Order Submission)──> WebSocket Pipe
  2. WebSocket Pipe ──(Stream Order)──> Node.js Sequencer
  3. Node.js Sequencer ──(Signed Receipt)──> WebSocket Pipe ──> Client Frontend
  4. Node.js Sequencer ──(Order Batch / IPC)──> Worker Thread Prover
  5. Worker Thread Prover ──(ZK Proof)──> Midnight Ledger
  6. Midnight Ledger ──(State Event)──> PostgreSQL Audit

================================================================================
                           PERFORMANCE TARGETS
================================================================================

  Order Processing Latency:     <1ms
  Soft Finality (Receipt):      <15ms
  Batch Proof Generation:       <5s (50 orders)
  WebSocket Throughput:         1000+ msg/s
  Memory Usage:                 <512MB
  Proof Verification:           <100ms (on-chain)
  Database Write (Async):       <500ms

================================================================================
                           SECURITY MODEL
================================================================================

  Witness Context:    Sees raw order data (locally encrypted)
  Sequencer Context:  Sees encrypted order frames only
  Circuit Context:    Sees encrypted batch data only
  Ledger Context:     Sees ZK proofs only (no trade data)
  PostgreSQL:         Sees finalized settlement records only
